## Rules that the table cannot show

- **Required** means required by the schema alone (`WEB_ORIGIN`, `DATABASE_URL`, `SESSION_SECRET` of at least 32 characters, the MFA key variables and `APP_ENV`). The configuration check adds conditional rules: `EMAIL_PROVIDER=smtp` needs `SMTP_HOST`, and `SMTP_USER` and `SMTP_PASSWORD` only together; `STORAGE_PROVIDER=s3` needs its `S3_*` settings and an https endpoint in production; `ASSISTANT_PROVIDER=anthropic` needs `ASSISTANT_API_KEY` and `ASSISTANT_MODEL` (and an https base URL in production); `REGISTRATION_MODE=code` needs `REGISTRATION_ACCESS_CODE` (12 to 200 characters) and that code is rejected in any other mode; the mock payment provider in production needs `PAYMENTS_MOCK_WEBHOOK_SECRET`. `server.ts` also refuses to start in production with `EMAIL_PROVIDER=mock`, which is the default, so set `EMAIL_PROVIDER=smtp` there. The MFA and webhook key variables are lists of `id:base64key` with an active id.
- **Cookies** are `Secure` in production and in staging, so the site must be served over HTTPS there.
- **Secrets** (`SESSION_SECRET`, the `*_KEYS`, the `DATABASE_*` passwords, `REGISTRATION_ACCESS_CODE`, `ASSISTANT_API_KEY`, `SMTP_PASSWORD`, `METRICS_TOKEN`) belong in a secret manager, never in Git. Back the encryption keys up separately from the database.
- `APP_ENV` is one of `development`, `testing`, `staging`, `production`. The container images and the production compose file set `production`.
