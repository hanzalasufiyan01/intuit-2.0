## How to read it

- **Status** words: `Built` (implemented and covered by named automated tests in the repository), `Built, partial` (works, with documented gaps), `Not built`, `Blocked` (needs an outside input), `Decision` (needs an owner decision first).
- **Evidence counts** are file counts matched by name keywords, so they are an indicator of where code and tests live, not a coverage percentage. The areas overlap (a file can match two). Source of the counts: a script run on 2026-10-27 over `apps/api/src/application`, `apps/api/src/api`, `apps/web/src/features`, `apps/api/test`, `apps/web/test`, `e2e` and the migrations.
- **Verified in a real environment** means a deployed instance with real providers. **No area has been verified that way.** Everything that has run, ran on the developer machine, on throwaway PostgreSQL servers, or on disposable GitHub Actions runners.
- The authoritative requirement-by-requirement list is `master-spec-coverage.md` (84 rows) and the prioritized plan is `remaining-scope.md`. Where this file and those disagree, trust them and fix this file.
